# C1: passthrough front end with hidden RECALL

HISTSH owns the user's terminal and runs DCL on a pseudo-terminal (NOTES N4). It
relays bytes both ways and leaves line editing and recall to DCL. Its only job is to
load DCL's recall buffer at the start and save it after every command, by typing RECALL
commands at the prompt where DCL honours them (N7), invisibly.

## Start

1. `HISTSH_START.COM` is called **at the end of SYLOGIN**, so the child inherits every
   symbol, logical and key the site set up (LIB$SPAWN copies them). It returns at once
   unless the login is interactive, on a terminal, not already inside HISTSH
   (`HISTSH$CHILD`), and the user holds `HISTSH$USER` (NOTES N3).
2. HISTSH defines process logicals that the child inherits: `HISTSH$CHILD`, `HISTSH$MARKER`
   (`<ESC>[?7777h`), `HISTSH$FILE` (the history file), `HISTSH$NEW` (a per-PID temporary).
   Short logical names keep the hidden commands short.
3. It copies the real terminal's characteristics to a new pseudo-terminal, spawns DCL on
   it with prompt `marker + "$ "`, and sets the real terminal to PASTHRU/NOECHO so Ctrl/Y,
   Ctrl/T and Ctrl/C reach the child as data. An exit handler restores the terminal.
4. At the child's first prompt, HISTSH types `@HISTSH:HISTSH_CHILD` and swallows its echo
   line. HISTSH_CHILD.COM runs the user's `SYS$LOGIN:LOGIN.COM` (visible, so INQUIRE works)
   and then re-applies the marker to whatever prompt LOGIN.COM set.
5. At the next top-level prompt, HISTSH types the hidden load: `RECALL/ERASE/INPUT=HISTSH$FILE`,
   or `RECALL/ERASE` when there's no file (so `@HISTSH:HISTSH_CHILD` never shows in history).

## Every command

State machine in `src/core/hs_relay.c` (pure, unit-tested):

| State | Child output | User keys |
| --- | --- | --- |
| BOOT | pass; first top-level marker → type boot command, go BOOT_ECHO | hold |
| BOOT_ECHO | drop up to the first LF, then RUNNING | hold |
| RUNNING | pass; top-level marker → hidden load (once), hidden save if a command was entered and nothing was typed ahead, else IDLE | pass, count as typeahead |
| IDLE (at prompt) | pass (markers here are redraws) | pass; Return after typing → a command was entered, go RUNNING |
| HIDDEN | drop until the next top-level marker → IDLE, report done, replay held keys | hold |

A hidden command is typed only from RUNNING with no typeahead. Otherwise it would run
after the user's typed-ahead command, and that command's output would be swallowed. When
there's typeahead, the save waits for a later prompt. Markers are always stripped from
the output. If a hidden command gets no prompt within 5 s, HISTSH stops waiting and
passes everything through again.

After a hidden save, HISTSH checks `HISTSH$NEW` (it exists and isn't empty), renames it
over the history file, and deletes the previous versions. If the save failed, the old
file stays.

## End

The child's LOGOUT ends it. Its completion AST wakes HISTSH, which restores the terminal
and exits with success, and HISTSH_START.COM logs the parent out. If HISTSH fails
*before* spawning, it returns an error and the login continues as plain DCL.

## Known limits (C1)

- 254 commands (DCL's buffer). With two sessions, each saves its own buffer: the last
  to save wins.
- `SET PROMPT` typed by the user drops the marker, so saving stops for that session.
  HISTSH warns once (to be done: put the marker back with a hidden command).
- LOGIN.COM is assumed to be `SYS$LOGIN:LOGIN.COM` (UAF /LGICMD isn't read yet).
- Two processes per session; the child counts against PRCLM and shares quotas.
